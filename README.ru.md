# Custom-Block — свои блоки для BONE:MSD одной строкой

[English](README.md) · **Русский**

> Проект сделан с помощью [Claude Code](https://claude.com/claude-code), ИИ-ассистента для программирования от Anthropic.
> Это касается генератора, переноса движка BONE:MSD на Minecraft 26.3, тестов и этой документации.

Блоки описываются списком в `blocks.json`, как значения enum. Генератор сам создаёт всё
остальное: предмет блока, loot tables, запись в креативе, модели, переводы и переопределения
ванильных файлов. На выходе получается один пак для **Minecraft 26.3**, в который уже входит
движок BONE:MSD.

```
Custom-Block/
├── blocks.json          ← ваш «enum» блоков (редактировать)
├── textures/            ← PNG-текстуры 16×16 (класть сюда)
├── slots.lock.json      ← какая плита за каким блоком (создаётся сам, НЕ удалять)
├── generator/build.py   ← генератор
├── engine-patches/26.3/ ← исправления, переносящие движок BONE:MSD на Minecraft 26.3
├── tests/               ← проверка сборки на настоящем сервере 26.3, без клиента
├── build/               ← результат: custom_blocks.zip (пересоздаётся при каждой сборке)
└── extension/           ← оригинальный движок BONE:MSD, пример и PDF автора (референс, не менять)
```

## Быстрый старт

1. Положите текстуру в `textures/`, например `textures/marble.png`.
2. Допишите запись в `blocks.json`:
   ```json
   { "id": "marble", "name": { "en_us": "Marble", "ru_ru": "Мрамор" }, "material": "stone", "texture": "marble" }
   ```
3. Соберите и установите в мир:
   ```bash
   python3 generator/build.py --install "<путь к папке мира>"
   ```
4. **Перезайдите в мир.** `/reload` не хватит: новые записи в креативе (картины) регистрируются
   только при загрузке мира. Если менялись только текстуры или модели, хватит F3+T.

Выдать блоки: `/function custom_blocks:give_all` или `/function custom_blocks:give/<id>`.
В креативе они лежат среди картин во вкладке «Функциональные блоки».

Нужен Python 3.9+, только стандартная библиотека.

## Поля блока

| Поле | Обязательно | Что значит |
|---|---|---|
| `id` | да | Имя блока: `a-z`, `0-9`, `_`. Если переименовать, уже поставленные в мирах блоки потеряются. |
| `name` | нет | Строка (en_us) или `{ "en_us": "...", "ru_ru": "..." }`. По умолчанию берётся из `id`. |
| `title` | нет | Подпись в креативе. Только `A-Z a-z 0-9` и пробел, других символов в шрифте движка нет. По умолчанию равна `name.en_us`. |
| `material` | нет | `wood` · `stone` (по умолчанию) · `copper` · `wool` · `concrete`. Задаёт звук, твёрдость, нужный инструмент и горючесть. |
| `texture` | * | Одна текстура на все стороны (модель `cube_all`). |
| `model` + `textures` | * | `cube_column` (`side`, `end`) · `cube_bottom_top` (`side`, `top`, `bottom`) · `cube` (`up`, `down`, `north`, `south`, `east`, `west`, необязательный `particle`). |
| `model_file` | нет | Путь к своей JSON-модели (например, из Blockbench) относительно `Custom-Block/`. Ключи `textures` дописываются в неё. Модель всё равно должна быть полным кубом (см. «Ограничения»). |
| `drop` | нет | Другая loot table для дропа, например `minecraft:blocks/oak_planks`. По умолчанию выпадает сам блок. |
| `creative` | нет | `false` — не показывать блок в креативе. |
| `slab` / `waterlogged` | нет | Закрепить блок за конкретной плитой, например `"slab": "oak_slab"`. Обычно не нужно. |

\* нужен либо `texture`, либо `textures`.

Значение текстуры без `:` — это файл `textures/<имя>.png`. Рядом можно положить `.png.mcmeta`
для анимации. Значение с `:` — готовая текстура, например `minecraft:block/calcite`.

Общие настройки `blocks.json`:
- `namespace` — пространство имён для сгенерированного содержимого (`custom_blocks`);
- `description` — описание пака;
- `minecraft_version` — пока только `26.3`. От неё зависят номера форматов и синтаксис данных:
  в 26.3 loot tables и предикаты сильно изменились (`modifier`, `condition`, `match_block`);
- `use_waterlogged_slots` — использовать и второе, «затопленное» состояние каждой плиты.
  По умолчанию выключено: в PDF описаны баги этих состояний;
- `reserved_slabs` — плиты, которые генератор не должен трогать, потому что их использует другой пак.

## Как это работает

**Слоты.** Каждый блок занимает состояние `<плита>[type=double]` одной ванильной плиты.
Движок BONE:MSD превращает поставленные игроком двойные плиты в полные блоки, поэтому это
состояние в мире свободно. Ресурспак рисует на нём вашу модель, а датапак подменяет дроп.
У блока нет entity: он быстрый, двигается поршнями и не рассинхронизируется.

Слотов на материал: wood — 13, stone — 45, copper — 4, wool — 16, concrete — 16.
С `use_waterlogged_slots` их вдвое больше.

**Стабильные слоты.** Слот выдаётся один раз и записывается в `slots.lock.json`, поэтому порядок
в `blocks.json` не важен. Если блок удалить, его слот «списывается» и не выдаётся новым блокам,
иначе уже поставленные в мирах блоки превратились бы в новые. Освободить списанные слоты
всё же можно: `python3 generator/build.py --free-retired`.

**Установка блока в мире.** Предмет блока — это barrier с данными `bone_cb`. Движок ловит
установку barrier, ставит на его место командный блок, и на следующем тике тот ставит
настоящий блок.

**Перенос движка.** Оригинальный движок (`extension/bone-msd-26-5`) в 26.3 **не загружается**:
мир открывается в безопасном режиме с ошибкой `Failed to parse bone_msd:block_engine/placed_block`.
Генератор копирует движок и накладывает сверху `engine-patches/26.3/`:
- новый формат advancement `placed_block`;
- новый синтаксис `item modify` в `update_slot`;
- пять block-тегов для редстоуна, которых не было в архиве автора.

В пак попадают только файлы, которые движок действительно использует. Черновики автора (`*-old`),
неиспользуемые текстуры шрифта и демо-строки в него не входят.

**Один пак в двух ролях.** У датапаков и ресурспаков в 26.3 разные номера форматов (121 и 97),
а `pack.mcmeta` у пака один. Поэтому в нём указан диапазон `min_format: 97`, `max_format: 121`.
Код самой игры признаёт такой пак совместимым в обеих ролях (проверено).

## Установка

Нужен только один файл — `build/custom_blocks.zip`, в нём и `data/`, и `assets/`.

**Автоматически:** `--install` (см. «Быстрый старт») копирует zip в `<мир>/datapacks/` и в папку
`resourcepacks/` того же инстанса игры. Старые версии наших паков он удаляет, а если там остались
оригиналы автора, предупреждает. Ресурспак нужно один раз включить в настройках игры.

**Вручную:** скопируйте `custom_blocks.zip` в `<мир>/datapacks/` **и** в `resourcepacks/`.

Оригинальный `bone-msd-26-5` и пример автора `bone-msd-example-pack` вместе с этим паком
**не ставить**: оригинальный движок ломает миры 26.3, а пример переопределяет тот же
`items/painting.json`.

Если что-то не работает, откройте `logs/latest.log` инстанса. Строки `Missing data pack`,
`Failed to load function`, `Failed to parse` и `Missing block model` показывают причину.

## Подсказка в креативе (omg_font)

`omg_font` — шрифт из ресурспака движка. Вместо букв в нём картинки:
- `…` — куски фона высотой 47px, похожие на ванильную подсказку (тёмная заливка,
  фиолетовая рамка);
- `…` — отступы, в том числе отрицательные;
- `A-Z a-z 0-9` — крупные буквы.

В креативе блок — это картина, и её подсказка выглядит так: «Картина» / название варианта /
автор / размеры. Название варианта набрано этим шрифтом. Его фон поднимается вверх, закрывает
строку «Картина» и рисует поддельную подсказку с именем блока. Ширина фона подбирается под имя
(`painting_title` в генераторе).

Строки **после** названия игра рисует позже, то есть поверх поддельной подсказки:
- **Размеры картины** («16 на 16»). Движок обнулял эту строку только для английского, поэтому
  в других языках она просвечивала. Генератор теперь обнуляет её во всех языках. Из-за этого
  размеры не видны и у обычных картин.
- **Расширенные подсказки F3+H**: `minecraft:painting` и число компонентов. Пак не может их
  убрать; для чистой подсказки выключите F3+H.

## Проверка без клиента игры

```bash
python3 tests/run_gametest.py
```
Скрипт берёт Java и jar 26.3 из Prism Launcher и запускает встроенный в Minecraft GameTest-сервер
с паком из `build/` и тестовым паком `tests/cbtest`. Примерно за 15 секунд он проверяет:
- что пак грузится без ошибок и предупреждений;
- что предмет блока содержит `bone_cb`;
- цепочку barrier → командный блок → установленный блок;
- дроп кастомных блоков и обычных плит;
- превращение картины в предмет блока.

Тест написан под примеры `split_oak` и `engraved_copper`. Ресурспак так не проверить:
его рисует только клиент игры.

## Ограничения

- **Только цельные блоки.** Блок — это двойная плита, поэтому его хитбокс, коллизия и
  затенение всегда как у полного куба. `model_file` неполной формы меняет только картинку
  и оставляет дыры в мире. Для своих плит и ступенек нужен другой механизм: из плит без рецепта
  есть только `petrified_oak_slab`, а таких ступенек нет вовсе. Пока это не реализовано.
- Текстуры должны быть непрозрачными: плиты рисуются как сплошные блоки.
- Средняя кнопка мыши в креативе выдаёт ванильную плиту, а не ваш блок.
- Если игрок собирает двойную плиту того же типа, на 1 тик мелькнёт кастомный блок
  (известная проблема движка).
- Двойные плиты, которые уже стоят в мире или созданы генерацией мира, станут кастомными блоками.
  Поэтому первыми выдаются редкие плиты (pale_oak, bamboo_mosaic, resin_brick…).
- Движок ставит блоки через командные блоки, поэтому на сервере нужен `enable-command-block=true`.
- Данные ставящегося блока движок хранит в одном общем storage. Если два игрока поставят
  кастомные блоки в один и тот же тик, оба получат блок второго.

## Авторство

BONE:MSD («Bhex's Over-Named Extension for Mod-Sized Datapacks») — автор Bhex. Оригинальный
движок, его пример и документация лежат в `extension/` без изменений, а текстуры в `textures/`
взяты из этого примера. Это чужая работа, она не относится к этому проекту, и все права на неё
принадлежат автору. По его просьбе эти файлы будут удалены.
